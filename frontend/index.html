01THE DIFFERENCE

Your tests check what you expected. BreakFix tests what you forgot to expect.

Most change reviews stop at a diff and a familiar test suite. That leaves the assumptions between the two invisible.

BreakFix makes those assumptions explicit, ranks them, and asks deterministic experiments to challenge them. The model proposes probes. The evidence decides.

Put a change under evidence ↗
02HOW IT WORKS

A review you can follow from change to proof.

The path stays bounded and visible. Every result has an evidence trail.

01

Read the change

BreakFix inspects the public repository, task, diff, and visible tests.

02

Find assumptions

BreakFix ranks the assumptions introduced by the change, then selects a bounded set of supported experiments worth executing.

03

Run the evidence

Isolated execution records expected behavior, actual behavior, and a reproducible verdict.

03WHAT THE RESULT MEANS

Evidence carries the decision.

A clean result is not called safe by implication. BreakFix reports exactly what the bounded run supports.

CONFIRMED BREAK
A targeted experiment caused the code to fail in the predicted way.
NO BREAK CONFIRMED
The selected supported experiments did not reproduce a break.
UNSUPPORTED
BreakFix could not map this change to a supported experiment surface.
ERROR
The run ended before BreakFix could produce a trustworthy verdict.
